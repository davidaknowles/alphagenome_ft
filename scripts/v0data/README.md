# v0data fine-tuning experiments

This directory contains dataset-specific preparation and experiment launchers for comparing low-rank adaptation, LoRA, with LoRA plus low-rank convolution adaptation, LoCon. All comparisons use the same 131,072 bp chromosome holdouts, initialization, optimizer settings, and signed double-centered Pearson correlation for model selection.

Every launcher appends `_smoke` to its checkpoint and Weights & Biases run name when `SMOKE=1`. Smoke checkpoints are therefore isolated from full-data histories even when a caller does not provide a distinct run suffix.

The current machine-readable and Markdown snapshots are `results/v0data_adapter_comparisons.json` and `results/v0data_adapter_comparisons.md`. Regenerate both with `collate_adapter_comparisons.py` after an evaluation checkpoint completes. The headline table uses the highest epoch completed by both strategies. A separate table reports independently selected checkpoints, where each epoch maximizes that run's mean validation signed double-centered correlation across heads. Scientific optimization variants are written separately to `results/v0data_objective_screens.json` and `results/v0data_objective_screens.md`, while native-species joint evaluations are written to `results/v0data_joint_species_evaluations.json` and `results/v0data_joint_species_evaluations.md`.

`audit_adapter_coverage.py` writes `results/v0data_adapter_coverage.json` and `results/v0data_adapter_coverage.md`. This report checks the canonical non-ENCODE experiment matrix for missing strategies and identifies the highest epoch completed by both strategies. A matched epoch is evidence that a comparison can be made at that depth, not that early stopping completed or that the target correlation was reached.

`audit_metric_targets.py` writes a separate modality-level audit against validation signed double-centered correlation 0.8. It distinguishes missing canonical evidence from a completed result below target and reports the stronger strategy-selected checkpoint without selecting separate favorable epochs for individual heads.

Canonical Liu and Johansen identities resolve only to the corrected raw-count, gene-only RNA runs with correlation weight one. The legacy Liu exon-plus-gene checkpoint is retained only as an explicitly labeled objective variant, while Johansen checkpoints based on per-cell-normalized expression are excluded because their targets are defective. Corrected run-directory aliases are mapped back to the study names in canonical coverage and result tables.

Each new `best` and `last` checkpoint stores optimizer state as well as model parameters and metrics. Continuation restores AdamW moments when that artifact is present. Older parameter-only checkpoints remain supported and start with a fresh optimizer state, which is reported explicitly in the training log.

`--pretrained-head-initialization bootstrap` initializes every new ATAC or RNA output channel from a deterministic, non-padding channel of AlphaGenome's corresponding pretrained head. Source channels are matched by strand when possible, and one assignment is shared across resolutions, biases, weights, and learned scales. This preserves coherent pretrained output directions without freezing or sharing the new head. The default `none` retains random initialization, and initialization cannot be reapplied when resuming a checkpoint.

`--pretrained-head-initialization neural_bootstrap` additionally restricts source-strand pools for target channels whose labels identify brain, neuronal, or macroglial populations. Vascular, immune, microglial, and non-brain multi-organ channels retain the assay-wide source pool. It excludes kidney and renal records whose names contain the ambiguous word cortex. Filtering is enabled only when at least two eligible source channels remain for every required strand; otherwise the affected head falls back to the assay-wide bootstrap instead of duplicating one source direction across all target channels. In the human pretrained model this filters eligible RNA channels, which have diverse neural sources, but leaves ATAC on the assay-wide fallback because only one neural ATAC track is available.

`audit_pretrained_head_sources.py` reads the released AlphaGenome metadata and records valid and neural source counts by organism, assay, and strand. This separates the candidate pool from the diversity fallback and keeps initialization decisions reproducible when model metadata changes.

`--pretrained-head-initialization neural_accessibility_bootstrap` uses neural DNase channels to initialize new ATAC heads while retaining the neural RNA behavior above. ATAC-seq and DNase-seq both measure chromatin accessibility, and their pretrained AlphaGenome heads use the same unsquashed 1 bp and 128 bp genome-track architecture. Human metadata provides 18 neural DNase channels compared with one neural ATAC channel. This cross-assay initializer remains a separately named screen because assay-specific scale and protocol effects may outweigh the closer tissue match.

`submit_pretrained_head_bootstrap_screens.sh` runs matched one-epoch LoRA and LoRA plus LoCon screens on HDA and Liu. HDA uses its canonical published-target objective, while Liu uses the raw-count, gene-only RNA objective with correlation weight 1 and no derived exon-coverage loss. The launcher defaults to the assay-wide bootstrap and accepts the neural initialization variants for separately named screens. `SMOKE_GATE=1` requires both strategies to complete one update before their full-data tasks become eligible. An initializer is advanced to the wider study panel only if it improves signed double-centered RNA correlation without a larger ATAC regression.

`select_pretrained_head_initialization.py` compares random, assay-wide, neural RNA, and neural DNase accessibility initialization across HDA, Liu, LoRA, and LoRA plus LoCon at epoch one. It selects by the equally weighted ATAC/RNA mean only when the overall score improves and neither modality's four-arm average regresses beyond the configured tolerance. The dependent CPU job uses `afterany`, so a failed accelerator screen reaches the selector and produces a direct missing-evidence failure instead of remaining indefinitely dependency-blocked.

`submit_hda_rna_only_screen.sh` isolates shared-adapter competition by retaining only the Mannens RNA head while leaving its canonical coverage-plus-gene objective unchanged. It uses neural accessibility bootstrap in both the RNA-only and corresponding joint screen, making RNA head initialization independent of whether ATAC is present. The matched one-epoch result is diagnostic and does not replace the paired canonical model. `retain_target_heads` provides the reusable manifest operation, while the launcher remains dataset specific.

`compare_hda_rna_isolation.py` compares epoch-one joint and RNA-only validation RNA correlation for each adapter strategy and their equal mean. Modality isolation is supported only when the mean improves and neither LoRA nor LoRA plus LoCon regresses beyond the configured tolerance. Run it directly after both smoke-gated full arrays complete; it is intentionally not dependency-submitted because an `afterok` smoke failure would otherwise leave another unresolved selector job.

`prepare_study_targets.py` creates deterministic manifests from published BigWigs. RNA heads receive the exact base-weighted mean over finite positive values for each track because the AlphaGenome RNA output transform uses this quantity for channel scaling. ATAC tracks remain in their native published units because earlier scalar and quantile normalization screens did not improve Allen performance.

The published-track comparison includes the Mannens fetal-brain ATAC panel, paired Mannens ATAC/RNA targets, all four Zemke 2023 motor-cortex species, and the all-age Zemke 2024 hippocampus ATAC/RNA panel. The all-age Zemke 2024 panel avoids mixing biological age effects into the first adapter comparison. Age-stratified channels will be evaluated after the shared cell-type baseline.

The Zemke 2023 comparison uses 20 published ATAC and 20 published RNA channels for human, macaque, marmoset, and mouse. Separate-species runs use each native reference assembly. Joint runs sample equal numbers of batches from each species, pool channel-wise RNA nonzero means, use AlphaGenome's human organism index for the three primates, and use its mouse index for mouse.

Predefined output heads allocate organism rows through the largest represented AlphaGenome organism index. A human-only head therefore has one row, while a mouse-only head has two rows and learns through row 1. Earlier mouse-only runs allocated one row from the metadata length, causing the mouse one-hot selector to be zero and disconnecting every output-head parameter. Those mouse results are superseded and are not valid LoRA versus LoCon comparisons.

`slurm_assert_zemke2023_mouse_gradients.sbatch` validates the corrected one-update LoRA and LoRA plus LoCon diagnostics before production mouse training. It requires finite nonzero ATAC and RNA output-head gradient norms from both strategies. This gate protects the canonical mouse comparison from advancing if organism-row selection is disconnected again.

`audit_target_differential_signal.py` samples matched-size genomic windows from one or more target manifests and reports sparsity, cross-track correlation, and the fraction of variance retained after double centering. This distinguishes weak prediction correlations caused by limited biological contrast from failures in model optimization or target alignment.

The training command's optional `--report-head-gradient-norms` diagnostic evaluates each head separately on the first training batch. It reports the unweighted loss, the L2 gradient norm on shared LoRA and LoCon parameters, the norm on that head's own parameters, the configured loss-weight-adjusted shared norm, and pairwise cosine similarity between shared-adapter gradients. Use these norms rather than raw loss magnitudes when choosing outer head weights, because different likelihoods can have different loss-to-gradient scales. `collate_gradient_diagnostics.py` writes the structured cross-run comparison to `results/v0data_gradient_diagnostics.json` and `results/v0data_gradient_diagnostics.md`.

`--evaluate-only` loads the requested checkpoint, evaluates the configured splits, and writes `evaluation.json` under the specified output directory without optimizer updates or model checkpoint writes. Joint cross-species checkpoints are evaluated once per native species manifest so pooled metrics cannot hide a species-specific failure. `submit_zemke_joint_native_evaluations.sh` derives the selected epoch from each joint strategy checkpoint, reconstructs the same two-organism joint model, and uses `--evaluate-species` to evaluate all four native datasets without changing checkpoint tensor shapes. `submit_johansen_joint_native_evaluations.sh` dependency-gates the corresponding three-species evaluations on each corrected strategy checkpoint. `collate_joint_species_evaluations.py` verifies source-epoch provenance for Zemke and Johansen checkpoints and produces a shared JSON and Markdown result table.

For a multi-species configuration, `--evaluate-species NAME` selects one species data module while retaining the shared model construction and pooled track-scaling metadata. It requires `--evaluate-only`. This is used for native-species evaluation of Johansen joint checkpoints so aggregate metrics cannot hide a weak primate.

Johansen targets use the three-primate, fragment-derived ATAC and exon-plus-gene RNA preparation. A shared group must have at least 500,000 whole-genome ATAC fragments in every species. This removes `SN GATA3-PVALB GABA`, whose human pseudobulk has only 33,424 fragments, and retains 47 aligned groups across human, macaque, and marmoset. The filter is applied synchronously to ATAC tracks, strand-specific RNA tracks, and gene-expression matrices so all species retain an identical head signature. Liu HDMA uses 186 paired clusters reconstructed from cell-assigned fragments and expression matrices because its released observed BigWigs are significance scores rather than normalized accessibility coverage. Those reconstructions are not replaced by model predictions or attribution tracks.

The initial Johansen RNA targets were derived from pseudobulks that summed per-cell normalized expression. `johansen_rna_reprocessing` instead sums raw unique molecular identifier, UMI, counts within each group and then normalizes to counts per million, CPM. In raw CPM space, legacy versus corrected double-centered agreement is 0.4645 for human and 0.5023 for macaque, so this is a target-composition correction rather than scalar rescaling. Legacy Johansen RNA training results are superseded. The corrected screen preserves existing gene annotations, uses direct gene supervision without derived exon coverage, and adds the global-batch signed-correlation objective.

The Johansen comparison includes matched human-only LoRA and LoRA plus LoCon baselines as well as joint human, macaque, and marmoset training. The human-only run uses the same reconstructed human targets, pooled channel scaling, chromosome holdouts, and optimizer settings as the joint run. It distinguishes a human target or objective limitation from cross-species gradient conflict before native-species joint evaluations are interpreted.

Reconstructed ATAC uses all selected fragments, 100 bp mean fragment coverage, and complete-library signal-per-million-reads normalization, without downsampling. Reconstructed RNA sums unique molecular identifier counts by cluster, normalizes to counts per million, writes strand-specific union-exon density, and retains direct gene-level supervision. Published Zemke tracks remain in their source reads-per-kilobase-per-million units because prior scalar and quantile normalization screens did not improve transfer.

`liu_hdma/audit_rna_reliability.py` reconstructs two sample-level RNA pseudobulk halves for each Liu group, reports raw and log1p CPM split-half signed double-centered correlation, and applies the Spearman-Brown correction to estimate full-pseudobulk reliability. With the modeled gene map and fixed-window geometry, it also stratifies reliability over the genes that actually enter each chromosome metric after genome-wide CPM normalization. At 131 kb, full-span containment retains 1,067 of 1,525 chromosome-8 genes and 972 of 1,340 chromosome-9 genes. Raw-CPM full-pseudobulk reliability is 0.9390 on validation chromosome 8 and 0.8650 on test chromosome 9. Greater target noise can therefore explain part, but not all, of the prediction gap because the assumption-based chromosome-9 correlation ceiling remains above 0.8.

`liu_hdma/audit_split_target_rank.py` compares the cell-group structure and gene leverage of the exact held-out metric support. In raw CPM, chromosome 8 has effective rank 5.32 and requires rank 2 for an optimal approximation to reach $R=0.8$, whereas chromosome 9 has effective rank 12.10 and requires rank 4. Chromosome 9 is therefore less reliable and structurally more complex. The log1p targets used by the magnitude loss require ranks 8 and 9, respectively. The audit also records the substantial gene omission caused by requiring a complete gene span inside one sequence window.

The optional `max_exon_overlap_scaled` gene-window assignment avoids requiring a complete gene span inside one sequence window. It assigns each gene exactly once to the non-overlapping window containing the most annotated exon bases, aggregates only exon segments inside that window, and scales their weights by total divided by observed exon length. This preserves the full-exon sum under a uniform-coverage assumption while exposing long and boundary-crossing genes to direct supervision. `prepare_gene_window_assignment.py` applies the reusable manifest option, and `submit_liu_exon_window_screen.sh` runs a smoke-gated one-epoch LoRA screen. Results must be cross-evaluated on both full-span and expanded supports before attributing a difference to training.

`johansen_rna_reprocessing/audit_donor_reliability.py` performs the corresponding donor-level audit for each Johansen species using raw unique molecular identifier counts, the 47 retained groups, and the exact modeled genes. The resulting reliability estimates distinguish an optimization deficit from a target-noise ceiling after the pseudobulk normalization defect has been corrected.

`hda_rna/audit_count_sampling_reliability.py` audits the Mannens RNA pseudobulks at the molecule-sampling level because the release lacks donor-resolved counts. Across 20 random binomial molecule splits of the exact 134 groups and 59,310 modeled genes, raw-CPM split halves reach mean signed double-centered \(R=0.9993\), with Spearman-Brown full-depth technical reliability 0.9997. The corresponding log1p-CPM split-half correlation is 0.8498. Sequencing depth therefore does not explain the model's raw-CPM correlation deficit, while the lower log-space repeatability supports adding the raw-CPM correlation objective. These values do not include biological donor or specimen variability.

For Liu, raw CPM split halves reach signed double-centered \(R=0.8969\), with estimated complete-pseudobulk reliability 0.9457. The log1p representation used by the baseline gene mean-squared-error objective reaches only \(R=0.5343\), with estimated reliability 0.6965. Because model selection evaluates raw CPM, RNA objective screens add signed double-centered correlation in raw CPM space rather than forcing marginal normalization or removing otherwise reliable groups.

Gene-supervised RNA heads may set `gene_supervision.coverage_loss_weight` to zero and request only the 128 bp output. In this mode the data module retains the RNA track metadata needed to scale and interpret channels, but it does not open or read the exon pseudo-coverage BigWigs and the trainer does not construct their coverage loss. Gene predictions, direct counts-per-million targets, optional signed double-centered correlation loss, and gene-level metrics remain unchanged. `prepare_gene_only_rna_config.py` and `slurm_hda_gene_only_screen.sbatch` compare this objective with the exon-coverage baseline at correlation weights 0, 0.1, 1, and 10.

The optional row-centered gene-correlation loss removes each gene's mean across cell groups but does not estimate and subtract a cell-group mean from each minibatch. CPM normalization makes the row-centered target nearly identical to the split-wide double-centered target, with cosine 0.99975 for Mannens, 0.99986 for Liu, and 0.99312 to 0.99691 for corrected Johansen. Across all native training windows, batches contain a median of 16 modeled genes for Mannens, 9 for Liu, and 1 for each Johansen species. Random Johansen batches are empty 34.9% to 38.9% of the time. Optional gene-aware ordering preserves every selected window exactly once and reduces empty Johansen batches to 7.6% to 15.8%. It is paired only with row-centered correlation because spreading sparse genes increases one-gene batches that have no local double-centered variance. `audit_gene_correlation_centering.py` records this approximation. `submit_hda_row_correlation_screen.sh` compares the row-centered Mannens objective. `submit_liu_row_correlation_screen.sh` prepares the corresponding corrected Liu objective, and `submit_johansen_row_correlation_screen.sh` derives its three-species screen from corrected raw-UMI supervision. The Liu and Johansen launchers enable gene-aware ordering. These experiments remain separate from canonical and minibatch-double-centered screens.

`prepare_gene_only_species_config.py` applies the same transformation to every native manifest referenced by a multi-species configuration and rewrites only the manifest paths. This supports matched Johansen screens without copying measured ATAC tracks, expression matrices, or references. It is also appropriate for Liu, where RNA supervision is measured at gene level and exon density is a derived localization auxiliary rather than observed read coverage.

`run_rna_target_rank_audit.sh` measures the optimal low-rank structure of double-centered gene-by-cell-group RNA targets in raw and log1p counts-per-million space. The rank-k correlation ceiling is based only on the target singular values and does not measure sequence-model accuracy. The audit is used to decide whether a factorized cell-group output head can retain enough target variation before implementing that model variant.

RNA manifests may set `output_rank` to replace the final organism-specific feature-to-track projection with two learned factors. For input features \(X\in\mathbb{R}^{N\times L\times D}\), the full projection \(W\in\mathbb{R}^{D\times C}\) is replaced by \(P\in\mathbb{R}^{D\times R}\) and \(Q\in\mathbb{R}^{R\times C}\), where \(N\) is batch size, \(L\) is sequence positions, \(D\) is embedding channels, \(C\) is strand-specific RNA tracks, and \(R\) is output rank. The implementation retains the predefined RNA head's bias, softplus output, learned scales, resolutions, strand metadata, coverage objective, and direct gene aggregation. Omitting `output_rank` leaves the full head unchanged. Rank 16 is the initial HDA screen because the target audit gives an optimal raw-CPM double-centered correlation ceiling of 0.9336 at that rank. Factorized heads use random initialization; pretrained channel bootstrap is rejected because its released weights parameterize a full \(D\times C\) projection rather than the two factors.

`prepare_factorized_head_config.py` applies this change to one RNA head without modifying the canonical targets or objective. `submit_hda_factorized_rna_screen.sh` compares matched LoRA and LoRA plus LoCon runs with only the Mannens RNA projection factorized, using a smoke-gated one-epoch screen.

The study, species, and joint launchers accept `CORRELATION_LOSS_WEIGHT` as an optional weight on one minus signed double-centered Pearson correlation. For gene-supervised heads the term uses direct gene expression; otherwise it uses the highest model output resolution compatible with the genomic target. Under data-parallel training, track means, counts, covariance, and variances are reduced across devices, so the term is exactly the correlation of the complete global batch without gathering prediction tensors. Baseline comparisons leave this unset. Optimization screens use distinct run suffixes and are compared only after the stabilized objective passes the no-variance gradient test and a full-data smoke run.

`submit_zemke_species_continuations.sh` resumes selected canonical species tasks and requires saved optimizer state by default. Its default task set is the matched macaque pair, which has only one completed epoch and retains AdamW state. Marmoset is not included by default because its older checkpoint lacks optimizer state and requires an explicit optimizer-reset decision.

`submit_hda_joint_matched_epoch3.sh` completes the missing LoRA plus LoCon HDA joint epoch three. It verifies that LoRA has already completed epoch three, LoRA plus LoCon is at epoch two, and the latter checkpoint has no optimizer state. The resulting AdamW restart matches the boundary used for the existing LoRA epoch-three continuation.

`submit_zemke2024_rna_correlation_screen.sh` adds signed double-centered correlation only to the RNA head and leaves the ATAC likelihood unchanged. The matched one-epoch screen uses weight 10 because an outer RNA weight of five already balanced first-batch adapter-gradient norms but did not improve the mean validation score. This tests objective alignment without another modality-scale change.

`submit_zemke2024_all_correlation_screen.sh` applies weight 10 to both published Zemke 2024 heads. The matched smoke-gated comparison is separate from the RNA-only screen, so it tests whether the ATAC improvement observed with the same all-head objective on Zemke 2023 human transfers to the hippocampal-aging panel. The launcher uses the runtime all-head override and does not rewrite the canonical manifest.

`submit_hda_cosine_lr_screen.sh` and `submit_liu_cosine_lr_screen.sh` test a lower peak learning rate with linear warmup and cosine decay. Each first runs a one-update LoRA smoke test and then trains for up to eight epochs with validation early stopping. These are optimization screens against the corresponding constant-rate canonical runs. A lower-rate LoCon arm is justified only when the LoRA screen improves the mean validation signed double-centered correlation.

The HDA gene-only double-centered sweep first trains LoRA at weights 0, 0.1, 1, and 10. `slurm_reevaluate_hda_gene_objectives.sbatch` restores each epoch-one checkpoint and recomputes validation and test metrics with the current metric implementation. `select_hda_gene_objective.py` requires those `evaluation.json` files and verifies their source epoch before comparing the same mean validation correlation used for joint checkpoint selection. The dependent CPU selector records all values and submits exactly one LoRA plus LoCon counterpart only when the best nonzero weight exceeds weight zero. Row-centered objectives remain a separate matched experiment and are not mixed into this selector.

Each head may also define a positive `loss_weight`, which defaults to 1. This outer weight rescales the head's complete optimization objective when heads are summed; it does not change the reported per-head loss or metric. For gene-supervised RNA, the existing `gene_supervision.loss_weight` and `coverage_loss_weight` still control the relative gene and exon-coverage terms inside the RNA head. `prepare_head_loss_weight_config.py` copies a canonical manifest and sets one outer head weight so modality-balancing screens do not alter baseline manifests.
